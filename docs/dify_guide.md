# 用 Dify 搭建同款智能客服（对照版）

> 项目里的智能客服是用 Python 自己实现的（`ai/rag.py`），方便做评测和定制。
> 很多公司用 Dify 这类平台做客服，这里给出用 Dify 搭同一套能力的步骤，面试时可以对比两种做法。

## 一、准备

- Dify：用官方云版（cloud.dify.ai）或 Docker 本地部署。
- 模型：在“设置 → 模型供应商”里添加 DeepSeek（对话模型）和一个 Embedding 模型（如硅基流动的 bge-m3）。

## 二、建知识库

1. 知识库 → 创建知识库 → 上传 `kb/docs/` 下的 7 个 Markdown 文件。
2. 分段设置：选“自定义”，分段标识符填 `##`，最大长度 500。这样每个“## 小节”是一段，和代码版的切片方式一致。
3. 索引方式：高质量（向量）；检索设置：**混合检索**，打开 Rerank（如有），Top K = 3，分数阈值 0.5。
4. 用“召回测试”输入 `eval/rag_cases.json` 里的问题，检查命中的是不是正确小节。

## 三、建客服应用（Chatflow）

```
开始 → 知识检索（选上面的知识库）→ 条件分支：有没有检索结果
                                      ├─ 有 → LLM（提示词见下）→ 回复
                                      └─ 没有 → 直接回复“帮您转人工客服”
```

LLM 节点的系统提示词（与 `ai/rag.py` 一致）：

```
你是“示例好物旗舰店”的客服助手。请只根据【参考资料】回答顾客问题。
【参考资料】{{#context#}}
要求：只用资料里的信息，资料里没有就回答“这个问题我需要帮您转人工客服确认”；
先直接回答，再补充条件或步骤，120 字以内；顾客投诉、情绪激动、涉及账户安全时，建议转人工。
```

## 四、工单分类工作流（Workflow）

两种做法：

- **纯 Dify**：开始（输入工单文本）→ 问题分类器节点（填 8 个类别和说明，见 `ai/tickets.py` 的 CATEGORIES）→ 不同分支设置不同的处理（例如“账户支付”分支直接通知安全组）。
- **调用项目接口**：开始 → HTTP 请求节点 `POST http://你的电脑IP:8000/tickets/classify`，Body `{"text": "{{#start.text#}}"}` → 拿到 category、urgency 继续后续流程。先双击 `启动接口.command` 启动接口。

## 五、两种做法的对比（面试可讲）

| | Dify | 代码实现（本项目） |
|---|---|---|
| 搭建速度 | 快，拖拽即可 | 慢，需要写代码 |
| 维护 | 运营同事可以自己改知识库、提示词 | 需要开发 |
| 检索策略 | 平台提供的几种 | 可以自定义（同义词扩展、阈值转人工、RRF） |
| 评测 | 召回测试为主，批量评测要自己做 | 有评测脚本，改动后一键对比效果 |
| 接入自己的系统 | 通过 API | 直接集成 |

结论：原型和标准场景用 Dify，需要深度定制和量化评测的部分用代码，再以接口形式接回 Dify / n8n。
